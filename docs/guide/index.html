KeyGate: hướng dẫn sử dụng

Kho khóa cho AI agent: agent chạy được lệnh cần mật khẩu, token, wallet Oracle mà không bao giờ đọc được giá trị. Tài liệu viết cho bản đang chạy trên laptop (Windows 11, khay kgw tray, relay Cloudflare, iPhone duyệt), cập nhật 12/11/2026. Người mới, chưa quen hệ thống: đọc trang giới thiệu trước.

Nắm nhanh
  • Secret nằm trong vault mã hóa ở ~/.keygate. Chỉ broker (icon khay KeyGate) giữ khóa giải mã, và chỉ trong RAM.
  • Agent gọi kg run --secret <tên> -- <lệnh>. Broker kiểm policy, xin bạn duyệt khi cần, chạy lệnh với secret và trả đầu ra đã che giá trị thành [kg:<tên>].
  • Duyệt một lần cho một cặp secret–lệnh thì broker nhớ (grant bền) tới khi bạn thu hồi. Trong phiên làm việc broker cấp luôn không hỏi.
  • Màn hình khóa hoặc bạn không ở máy: yêu cầu duyệt bay sang iPhone. Quá 270 giây lệnh trả mã 75; duyệt xong thì chạy lại lệnh.
  • Không có lệnh nào trả giá trị secret về cho agent. Muốn xem giá trị: kg reveal, hiện trong hộp thoại tại máy.

Kiến trúc

Giá trị secret chỉ xuất hiện ở hai nơi: trong RAM broker và trong môi trường của tiến trình con broker chạy. Socket giữa kg và broker chỉ chở tên secret và argv. Relay Cloudflare lưu bản ghi đã mã hóa và chuyển thư duyệt; nó thấy ID vault, ID thiết bị, thời điểm, nhưng không thấy tên hay giá trị secret.

Ranh giới tin cậy đã chấp nhận (11/11/2026): mã PWA do Worker Cloudflare của bạn phục vụ và điện thoại duyệt được mọi loại yêu cầu, kể cả policy apply. Tài khoản Cloudflare vì vậy là một phần gốc tin cậy cho quyền duyệt; vault key và giá trị secret vẫn không nằm trên điện thoại hay Worker.

Cài đặt lần đầu

1. Build

cd D:/repos/keygate
go build -o kg.exe ./cmd/kg
go build -ldflags "-H=windowsgui" -o "$(go env GOPATH)/bin/kgw.exe" ./cmd/kg

Đặt kg.exe và kgw.exe vào PATH. Hook của agent cần thấy kg trong PATH.

2. Tạo vault

kg init --label laptop

Nhập mật khẩu chủ hai lần (ít nhất 12 ký tự). Lệnh in khóa giấy một lần duy nhất: chép tay hoặc in ra, cất cùng chỗ với giấy tờ quan trọng. Không dán vào chat, file, ghi chú điện tử.

3. Gắn relay

cd relay
npx wrangler login                 # một lần
# wrangler.toml: ALLOWED_VAULTS = "vlt_xxxxxxxx"  (lấy từ KG_HOME/vault.json)
npx wrangler deploy
kg channel add --relay-url https://keygate-relay.<tài-khoản>.workers.dev

kg channel add đòi mật khẩu chủ + khóa giấy, đẩy sự kiện khởi tạo lên relay rồi sync. Chạy khi broker đang tắt.

4. Cho broker tự chạy khi đăng nhập

powershell -File tools/install-autostart.ps1

Tạo task "KeyGate broker" chạy kgw tray. Đăng nhập Windows xong, Windows Hello hiện lên: xác nhận là vault mở và phiên làm việc bắt đầu. Log ở KG_HOME/broker.log.

5. Ghép điện thoại

Xem mục Duyệt bằng điện thoại.

6. Nạp secret, viết policy, chuyển script

kg import --dotenv D:/repos/abc/.env --prefix abc/ --env dev
notepad %USERPROFILE%\.keygate\policy.yaml
kg policy apply
kg import --dotenv D:/repos/abc/.env --prefix abc/ --compare   # phải ra toàn "same"

Sửa script của repo để đọc giá trị từ biến môi trường mà kg run cấp (không đọc .env). Khi --compare báo toàn same và smoke qua kg run chạy đúng, mới gỡ giá trị khỏi .env.

Menu khay

  • Mở khóa + mở phiên, Kết thúc phiên, Khóa.
  • Thêm secret: hộp thoại nhập tên, metadata và giá trị (ô ẩn). Giá trị không vào log.
  • Thiết bị…: danh sách thiết bị (nguồn lúc ghép, hoạt động gần nhất, giờ ghép), Ghép điện thoại…, Thu hồi.
  • Nhật ký, Thoát.

Phiên làm việc

kg session start   # một lần Hello
kg session end     # không hỏi; xóa grant của phiên, grant bền còn nguyên
kg lock            # khóa ngay, đồng thời kết thúc phiên
kg status          # khóa/mở, phiên, epoch, pin policy, grant, số điện thoại duyệt, yêu cầu chờ

Mặc định broker không tự khóa khi rảnh hay khi Win+L; job đêm của agent vẫn chạy được. Muốn chặt hơn: chạy broker với --idle 30m và/hoặc --lock-on-screen-lock (chỉ áp ngoài phiên).

Dù đang trong phiên, các thao tác sau luôn hỏi: policy apply, reveal, delete, ghi đè secret (set/import), import --compare, same, cp, resolve-conflict, thêm/thu hồi thiết bị. Secret PROD không có grant đúng tên vẫn bị từ chối.

Chạy lệnh với secret

# Oracle TEST1 qua wallet tạm (kind oracle-wallet)
kg run --secret ebs/test/apps -- sql /@ebs_test @D:/repos/x/sql/check.sql

# Token vào biến môi trường (kind env)
kg run --secret mantis/mantis-api-token -- python D:/repos/x/scripts/mantis_api.py me

# Nhiều secret một lần, một lần duyệt cho cả lô
kg run --secret abc/db-user --secret abc/db-password -- python D:/repos/abc/scripts/etl.py

# Script shell đã ghim trong policy
kg run --secret dns/api-token -- bash D:/repos/x/scripts/renew-cert.sh

Secret đến tay chương trình thế nào

kindChương trình nhận
envBiến môi trường tên env_name.
fileFile tạm quyền 600, đường dẫn trong KG_FILE_<TÊN> (hoặc env_name).
oracle-walletThư mục wallet tạm + tnsnames.ora, sqlnet.ora, ojdbc.properties; biến TNS_ADMIN trỏ vào đó. Kết nối bằng /@<tns_alias>.
templateDùng với kg resolve <file> -- lệnh: thay ${secret:TÊN} trong file, ghi file tạm, đường dẫn trong KG_RESOLVED.

File tạm và wallet nằm dưới KG_HOME/run/, bị ghi đè rồi xóa sau khi lệnh xong; broker khởi động lại thì dọn phần sót.

Đầu ra và mã thoát

  • stdout và stderr gộp một luồng. Giá trị secret xuất hiện nguyên văn, dạng base64 hay URL-encode đều bị thay bằng [kg:<tên>]. Không che được: hex, chuỗi đảo, UTF-16, nén, giá trị dưới 4 ký tự.
  • Mã thoát = mã thoát của tiến trình con. 1 = KeyGate từ chối (đọc dòng kg: …). 75 = đang chờ duyệt.
  • Tiến trình con chạy quá max_runtime (mặc định 30 phút) bị diệt cả cây.
  • SQLcl luôn chạy với -R 4: host, spool, @ lồng nhau bị chặn; set heading/pagesize/linesize báo SP2-0738 nhưng script vẫn chạy.

Viết policy

oracle:
  java: C:/Program Files/Eclipse Adoptium/jdk-21.0.10.7-hotspot/bin/java.exe
  pki_jar: C:/Users/me/AppData/Local/Programs/Oracle/SQLcl/current/lib/oraclepki.jar
  tns_admin: C:/DevSuiteHome_1/network/admin
grants:
  ebs/test/*:
    kind: oracle-wallet
    tns_alias: ebs_test
    allow_commands: ["sql /@ebs_test @path:D:/repos/x/sql/**/*.sql"]
    approval: user-presence
    max_runtime: 10m
  mantis/mantis-api-token:
    kind: env
    env_name: MANTIS_API_TOKEN
    allow_commands: ["python path:D:/repos/x/scripts/mantis_api.py"]
    approval: user-presence
    ttl: 8h
  dns/api-token:
    kind: env
    env_name: DNS_API_TOKEN
    allow_commands: ["C:/Program Files/Git/bin/bash.exe path:D:/repos/x/scripts/renew-cert.sh !exact"]
    approval: user-presence

Sửa xong luôn chạy kg policy apply: broker in diff từng grant, gắn cờ approval: none, wildcard, PROD, và chỉ ghi pin sau khi bạn duyệt.

Duyệt bằng điện thoại

Ghép iPhone

  1. Khay KeyGate → Thiết bị… → Ghép điện thoại…: hiện QR và liên kết ghép nối.
  2. Trên iPhone, mở liên kết bằng Safari → Chia sẻ → Thêm vào Màn hình chính. Mở KeyGate từ màn hình chính (không dùng tab Safari).
  3. Dán liên kết ghép nối vào app, bấm Bắt đầu. App hiện 6 từ xác nhận; laptop tự nhận mã từ điện thoại (hộp QR tự đóng).
  4. Trên laptop so 6 từ trên hai màn hình. Khác một từ thì dừng. Giống hết thì Đúng, thêm thiết bị.
  5. Nhập mật khẩu chủ + khóa giấy. Xong, kg status báo Điện thoại duyệt: 1 thiết bị.

Kiểm tra thông báo đẩy và khóa của app: mở <relay>/app/diag.html trên điện thoại.

Khi nào điện thoại được hỏi

  • Màn hình laptop đang mở: Windows Hello hiện trước; sau 15 giây chưa trả lời thì điện thoại cũng được hỏi, bên nào trả lời trước thắng.
  • Màn hình đang khóa: hỏi điện thoại ngay.
  • Có grant bền hoặc đang trong phiên: không hỏi ai, không có thông báo.
  • Chỉ làm tại máy, không bao giờ qua điện thoại: reveal, ghi đè secret, same, cp, nhập giá trị bằng hộp thoại, thu hồi thiết bị.

Quyết định gắn với bản băm của yêu cầu (thao tác, secret, lệnh, nội dung sẽ áp dụng) và chỉ dùng một lần. Nếu .env hay policy.yaml đổi sau khi duyệt, lần chạy lại tạo yêu cầu mới.

Mã thoát 75

Lệnh chờ quá 270 giây (giới hạn tool của agent là 300 giây) thì in kg: đang chờ duyệt trên điện thoại (KeyGate, yêu cầu abc123) và thoát mã 75. Yêu cầu vẫn mở trên điện thoại; duyệt trong vòng 10 phút rồi chạy lại đúng lệnh cũ là chạy được, không hỏi lại.

Điện thoại còn làm được: khóa, mở khóa + phiên, kết thúc phiên, thu hồi grant, thêm secret (giá trị niêm phong riêng cho laptop).

Grant

kg grants                          # secret, mẫu lệnh, by=hello|remote:<dev>|session|none, lúc cấp, hạn, bền/tạm
kg grants revoke mantis/mantis-api-token
kg grants revoke --all

Thu hồi không cần mở khóa và không hỏi (chỉ giảm quyền). Sửa policy bỏ một mục allow_commands thì grant bền của mục đó bị xóa khi policy apply.

Thiết bị, đồng bộ, khôi phục

Thêm máy tính thứ hai

# máy mới
kg device request --label mac-nha        # in mã đăng ký + 6 từ
# laptop (broker tắt, hoặc dùng khay Thiết bị…)
kg device add <mã>                       # so 6 từ, gõ yes, mật khẩu chủ + khóa giấy; in vault ID + ghim genesis
# máy mới
kg sync --via relay --relay-url <URL> --vault vlt_… --pin <ghim>

Đồng bộ

kg sync                    # dùng kênh trong vault.json
kg sync --via git --git-dir D:/sync/kg
kg sync --verify-via git   # so trạng thái qua git với qua relay, khác thì báo ErrFork
kg fingerprint             # 6 từ đại diện trạng thái; hai máy phải ra giống nhau

Thu hồi thiết bị

  • Điện thoại duyệt: khay → Thiết bị… → Thu hồi, chỉ cần Windows Hello. Không đổi epoch.
  • Máy tính (thiết bị đầy đủ): cần thêm mật khẩu chủ + khóa giấy. Broker tạo epoch mới, mã hóa lại mọi secret và ghi vào broker.log danh sách secret máy đó từng giải mã: đổi các secret này ở hệ thống đích.

Mất laptop

kg recover --from https://keygate-relay.<tài-khoản>.workers.dev --label laptop-moi --vault vlt_… --members-file members.kgl

Cần mật khẩu chủ + khóa giấy. Sau đó từ máy mới thu hồi laptop cũ.

Tích hợp AI agent

Claude Code

  1. Gộp integrations/claude-code/settings.snippet.json vào ~/.claude/settings.json (thêm vào mảng hooks.PreToolUse nếu đã có, không ghi đè).
  2. claude mcp add keygate -- kg mcp hoặc gộp mcp.snippet.json vào .mcp.json.
  3. Khởi động lại; thử bảo agent cat .env: phải bị chặn với lý do tiếng Việt.

omp

  1. Chép integrations/omp/keygate-hook.ts vào %USERPROFILE%\.omp\agent\hooks\pre\. Thiếu kg trong PATH thì hook cảnh báo và cho qua; lỗi khác thì chặn.

Hook chặn gì

Đọc/grep .env, .env.*, *.sso, *.p12, cwallet*, thư mục KG_HOME; env, printenv, set, Get-ChildItem Env:; kg reveal; mật khẩu gõ thẳng trong lệnh (user/pass@, --password=, Authorization: Bearer …, PASSWORD=…).

echo '{"tool_name":"Bash","tool_input":{"command":"cat .env"}}' | kg hook check ; echo $?   # 2 = chặn
echo '{"tool_name":"Bash","tool_input":{"command":"cat README.md"}}' | kg hook check ; echo $?   # 0

Nhật ký audit

Mỗi dòng ghi: sự kiện (grant, run-start, run, deny, reveal, set, import, policy, device-add…), secret, env, argv, nhãn agent tự khai, peer (PID/đường dẫn tiến trình gọi), kiểu duyệt (session, user-presence, remote:<dev>), mã thoát. Ghi audit lỗi thì lệnh không chạy.
